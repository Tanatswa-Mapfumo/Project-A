# Adaptive Fitness Coach — Backend

FastAPI backend for the Adaptive Fitness Coach proof of concept: an AI-driven
fitness app for general users pursuing fat loss, muscle gain, strength, or
mobility. Workouts are generated by a **deterministic adaptation engine** (never
by the LLM); an LLM only **explains** the structured facts the engine produced.

## Architecture

- **Modular monolith**: FastAPI + SQLAlchemy 2 (async) + PostgreSQL.
- Layers: `api` (routers) -> `schemas` (Pydantic) -> `services` (business logic)
  -> `repositories` (data access) -> `db/models`.
- `rules/`: pure deterministic rules (recovery, intensity, soreness, equipment,
  duration, progression) — unit-testable without a database or network.
- `ai/`: provider adapter (Gemini-compatible + deterministic mock). The LLM
  never writes to the database and never chooses exercises.
- Auth: Supabase Auth in staging/production; a local **mock auth mode** for
  development and tests (PBKDF2-hashed passwords, no raw passwords ever stored).

## Prerequisites

- Python 3.12+
- Docker (for the local PostgreSQL + full-stack dev)
- A Supabase project for staging auth (optional for local dev)

## Local setup

```bash
cp .env.example .env          # adjust values if needed
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
docker compose up -d db       # local PostgreSQL
alembic upgrade head          # apply migrations
python -m scripts.seed        # idempotent catalog seed
uvicorn app.main:app --reload # http://localhost:8000
```

Swagger/OpenAPI: <http://localhost:8000/docs> — every endpoint is documented
with request/response examples and error codes.

### Without Docker

Tests run on SQLite with no external services. For local development without
Docker you can also run the API on SQLite:

```bash
export DATABASE_URL=sqlite+aiosqlite:///./dev.db
export DATABASE_URL_SYNC=sqlite:///./dev.db
python - <<'EOF'
import asyncio
from app.db.base import Base
from app.db.session import engine
import app.db.models
async def main():
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)
asyncio.run(main())
EOF
python -m scripts.seed
uvicorn app.main:app --reload
```

## Environment variables

| Variable | Purpose | Default |
| --- | --- | --- |
| `APP_ENV` | `development` / `test` / `staging` / `production` | `development` |
| `DATABASE_URL` | async SQLAlchemy URL | local Postgres |
| `DATABASE_URL_SYNC` | sync URL used by Alembic | local Postgres |
| `AUTH_MODE` | `supabase` or `mock` | `mock` |
| `SUPABASE_URL` / `SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY` | Supabase config (staging) | empty |
| `MOCK_JWT_SECRET` | dev-only JWT secret for mock auth | dev value |
| `AI_PROVIDER` | `gemini` or `mock` | `mock` |
| `GEMINI_API_KEY` / `AI_MODEL` | Gemini provider config | empty / `gemini-2.0-flash` |
| `AI_TIMEOUT_SECONDS` | AI call timeout (falls back on timeout) | `2.5` |
| `FRONTEND_ORIGINS` | comma-separated CORS origins | localhost dev ports |
| `ENABLE_DOCS` | expose `/docs` and `/openapi.json` | `true` |

`SUPABASE_SERVICE_ROLE_KEY` must never be shared with frontend developers.

## Database migrations

```bash
alembic upgrade head
alembic downgrade -1          # where practical
alembic revision --autogenerate -m "change description"   # after model changes
```

## Seed data

```bash
python -m scripts.seed        # idempotent
```

## Tests

```bash
pytest
ruff check .
```

Unit tests cover the pure rules; integration tests cover repositories, auth,
ownership, generation persistence, session transitions, and progress
aggregation on an isolated SQLite database per test.

## Docker

```bash
docker compose up --build     # API on :8000, Postgres on :5432
```

The container runs as a non-root user and reads configuration from environment
variables only (no secrets are baked into the image).

## Staging deployment

- Target host: Koyeb, Render, or an equivalent low-cost host. The container is
  portable; any host that runs `uvicorn app.main:app` on `$PORT` works.
- Create the staging database, then run `alembic upgrade head` and
  `python -m scripts.seed`.
- Set `AUTH_MODE=supabase` plus the Supabase keys, configure CORS with the
  frontend origin(s), set `AI_PROVIDER=gemini` and `GEMINI_API_KEY` (or leave
  `mock` — generation still works and falls back to template explanations).
- Verify `/api/v1/health`, `/docs`, signup, check-in, and workout generation
  before sharing the URL (see `docs/frontend-api.md`).

## Test users

```bash
python -m scripts.create_test_user.py [email]
```

In mock mode the script creates a local account and prints a generated
password. In supabase mode it uses the service-role key (keep it server-side).
